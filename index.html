LEMP Stack — Ubuntu Server
2025  ·  lemp-stack-ubuntu-server
Full LEMP stack (Linux, Nginx, MySQL, PHP 8.3-FPM) deployed on a bare Ubuntu server for hosting a PHP web application with a relational MySQL database.
Stack
ComponentTechnology
Web ServerNginx
BackendPHP 8.3-FPM
DatabaseMySQL
OSUbuntu Server
Architecture
Ubuntu Server
├── Nginx :80
│   └── PHP 8.3-FPM
│       └── PHP Web App → MySQL (dbfarm2)
└── SSH Access (key-based)
How It Works
Nginx receives browser requests and forwards .php files to PHP-FPM for processing. PHP-FPM communicates with MySQL to fetch or store data. fix_permissions.sh sets correct ownership to www-data. db_import.sh creates the schema.
Errors Encountered
502 Bad Gateway — PHP-FPM was not running. Verified socket path matched installed PHP version.
MySQL Access Denied — Recreated user with correct credentials and re-granted privileges.
Takeaways
  • Nginx + PHP-FPM is faster and more memory-efficient than Apache + mod_php
  • Always run mysql_secure_installation before exposing a server
  • Web root permissions must be set to www-data to avoid 403 errors
LEMP Stack — Android proot
2026  ·  proot-lemp-android
Full LEMP stack running inside a proot Debian environment on Android ARM64 via Termux. No root, no laptop, no cloud — Nginx 1.26.3, PHP 8.4-FPM, MariaDB 11.8.6.
Stack
ComponentTechnology
Web ServerNginx 1.26.3 (port 8080)
BackendPHP 8.4-FPM
DatabaseMariaDB 11.8.6
OSDebian 13 (proot)
PlatformAndroid ARM64
Architecture
Android Phone → Termux → proot Debian
  ├── Nginx :8080
  │   └── PHP 8.4-FPM → Farm Management System
  │       └── MariaDB → dbfarm2
  └── Acode Editor (via symlink)
How It Works
proot creates an isolated Debian environment inside Termux. Services are started manually — no systemd in proot. Nginx runs on port 8080 since proot cannot bind privileged ports. Acode editor accesses files via a symlink bridging proot to Termux storage.
Errors Encountered
Port 80 Permission Denied — Changed Nginx to listen on port 8080.
ping binary missing — Installed iputils-ping and set SUID bit for www-data.
Takeaways
  • A modern Android phone is capable of running a full production-style web stack
  • proot limitations are all workable with small configuration adjustments
  • Symlinks bridge proot filesystem to Termux for seamless mobile editing
DVWA Pentest Writeup
2026  ·  dvwa-pentest-writeup
Full web application penetration test on DVWA covering 10 attack vectors, conducted entirely on Android ARM64 proot Debian.
Attack Chain
01 SQL Injection       → full database dump
02 Hash Cracking       → all passwords recovered (hashcat + rockyou)
03 XSS Reflected       → session cookie stolen
04 XSS Stored          → persistent cookie theft on all visitors
05 XSS DOM             → client-side execution, bypasses WAF
06 Brute Force         → valid credentials found (curl loop)
07 Command Injection   → RCE via web shell deployment
08 File Upload         → RCE via shell.php
09 CSRF                → account takeover via GET request
10 Blind SQL Injection → database enumeration character by character
Tools
ToolPurpose
hashcatMD5 hash cracking
curl loopBrute force (Hydra ARM bug workaround)
mitmproxyHTTP traffic interception
shell.phpWeb shell for RCE
Takeaways
  • DOM XSS is the hardest to detect — payload never reaches the server
  • Stored XSS is the most dangerous — one payload affects all visitors indefinitely
  • Command injection + file upload both lead to full RCE through different paths
